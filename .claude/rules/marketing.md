# Marketing layer boundaries

> **State after M0 (2026-10-08).** The public site is a provisional ONE site in Portuguese: a home, the waitlist, contact, help, blog and the legal pages. The pages that sold flyee.club are gone. The `marketing-page` skill and `docs/DESIGN.md` were written for that product: their examples (the app store, the terminal, the founders offer, an English twin of every page) no longer apply, while the rules below do.

- **One design system.** Every public page composes the primitives in `apps/web/src/components/marketing/`: `Section`/`Container`/`SectionHeader` plus the archetypes listed in `catalog.json`. Never hand-tuned per-page spacing or widths, never a parallel stylesheet vocabulary.
- The `marketing-page` skill is MANDATORY for any create/edit/add-section under `app/[locale]/(marketing)`, `app/[locale]/(funil)` or `components/marketing`. The `PreToolUse` hook (`.claude/hooks/marketing-guard.mjs`) loads it automatically on Write/Edit in all three, and the `PostToolUse` lint (`.claude/hooks/marketing-lint.mjs`) checks every written file there. A file changed by a script bypasses both hooks: load the skill yourself and run the lint on it by hand.
- **Visual direction.** ONE has not committed its own direction yet: the palette (`theme-blue`), the logo and the type are provisional. Until it does, new pages and sections INHERIT what the components already do. Never restyle the UI or change the palette, the type or the logo unless the user explicitly asks. Adding a section triggers a whole-page coherence pass so all sections stay aesthetically aligned.
- **One language, in the path.** ONE is written in Portuguese only. Every public page lives under `app/[locale]/` in a folder named after its address, and is declared in `apps/web/src/i18n/routing.ts` (`pathnames`). That declaration is also what makes the middleware treat it as public: there is no separate list of public pages. Sign-in, the logged area, checkout and the admin have no locale in the URL.
- Internal links on public surfaces go through `LocaleLink` (`components/marketing/locale-link.tsx`, also as MUI's `LinkComponent`) or `localizeHref`: `href` is the internal path and the link renders the public address. Links to `/auth/*` and other non-public routes pass through unchanged.
- An INDEXED page also goes to `apps/web/src/app/sitemap.ts`. A `noindex` page (`/espera/confirmar`, `/descadastro`, any campaign page) stays out of the sitemap and is named in its exclusion comment. Indexing is decided by `metadata` + `sitemap.ts`, never by the route group.
- `/ajuda` and `/blog` are DB-managed: content is written in `/admin/help` / `/admin/blog` and fetched through `apps/web/src/lib/public-content.ts` (anon client, published rows). Content that could not be read is never shown as an empty list. Markdown renders via `components/marketing/markdown-prose.tsx`. Never interpolate DB content as raw HTML.
- SEO is part of every page: exactly one `<h1>` (the page title: `SectionHeader as="h1"` / `PricingSection headingAs="h1"` when the lead is not a `<Hero>`), a title + description via `generateMetadata` that spreads `publicPageMetadata({ path, locale })` from `lib/seo.ts` (canonical, Open Graph URL and locale), and structured data through `<JsonLd>` (`components/marketing/json-ld.tsx`), never a hand-written `<script>`. `Organization`/`FAQPage`/`Product` schemas are already emitted by the layout/`Faq`/`PricingSection`; do not duplicate them. Inner pages add `BreadcrumbJsonLd`. A missing page answers a real 404 and a moved one a real redirect: never put a loading boundary (`loading.tsx`, or a `<Suspense>` around the children of a layout) above a public page, because the response would start before `notFound()` or `redirect()` runs and go out as a 200.
- Marketing copy lives in the `marketing` namespace of `packages/content/messages/pt-BR.json`. No hardcoded strings.
- **Blocking on every public page**: exactly one `<h1>`, real `alt` text, no fabricated testimonials, metrics, logos or case results, prices and limits read from data (`plans`), no struck-through price and no "from/to" pair. Every number on a public page comes from the database.
- **What the site may say about the product.** ONE is software for law firms, sold by a technology company: it never promises the outcome of a lawsuit, an amount of compensation or a time to judgment, never speaks to passengers as if it were a law firm, and never says a step is automatic when a lawyer decides it (filing is assisted: the lawyer reviews and files with their own login).
- **Copy rules**: Portuguese, plain; no dash (— or –), no exclamation mark and no emoji in any visible text, `alt` and `aria-label` included (© and → stay, on purpose), and none of the banned words: desbloqueie, potencialize, sem esforço, soluções inovadoras. Where a dash would go, write a colon, a comma or a new sentence; separate items with "·"; a missing value hides its line instead of printing a placeholder. The rule covers the logged area, the e-mails, the bell and WhatsApp messages too; `lib/i18n/copy-rules.test.ts`, pgTAP `0033_copy_rules` and the e2e text check fail when a mark comes back.
- **Colour on text**: under the provisional palette no hue reaches 4.5:1 as small text on a light ground, so hues go on icons, bars and fills while the words keep text colours. The shared components follow it; a page must too.
- Motion is CSS first: the hero entrance and `Float` are CSS animations, `Reveal` is a CSS transition started by `watchEntry` (one shared IntersectionObserver in `components/marketing/motion.ts`), `CountUp` is a short frame loop. GSAP is loaded by `Parallax` alone, on demand. Never add a scripted timeline or a ScrollTrigger to a page, and never an animation without an end. Transform + opacity only, honoring `prefers-reduced-motion`. Never import GSAP in admin code.
- Site identity (name, tagline, siteUrl, favicons) comes from `apps/web/src/brand.ts`; the logo is the single component `components/logo/logo.tsx`.
- **Measurement is declared, never a new tracker.** A click worth measuring carries `data-track="<event>"` and `data-track-<prop>` attributes (or `trackAttributes()` from `lib/site-events.ts` on a link built in code), a section worth measuring passes `track="<key>"` to `Section` or the component that wraps one, and the one listener in `MarketingAnalytics` reports them to GA4 and the Pixel. The vocabulary is the type in `lib/site-events.ts` (`section_view`, `cta_click`, `faq_open`, `contact_click`): add to it there before using a new name. Never add PostHog or any other tracker, never write site events to the database, and never run a tracker inside the logged area or on a page a passenger opens by token.
